# Project: frank-lloyd-aight (Frank Lloyd AIght)

A standalone architecture plugin with a Claude Code agent in `agents/frank-lloyd-aight.md` and a portable skill in `skills/frank-lloyd-aight/SKILL.md`. It reviews the drawings and never pours the concrete.

## Rules

- **TDD.** Behaviour starts as a failing eval case. The agent file changes only to turn a red case green.
- **Evals run against real `claude -p`.** Every run is sandboxed: temp fixture dir outside this repo as cwd; `--setting-sources project` (no user settings or user plugins); `--strict-mcp-config` with no user MCP servers, only harness mocks; `git commit|add|push`, `rm`, and `rmdir` denied unless the case's own `sandbox` says otherwise, a case with `"git": true` gets git by named subcommand (`GIT` in `run.py`; `Bash(git:*)` is refused, since an alias can run a shell), every run's git is cut off from the user's global and system config and held to the file transport, so a case that allows push reaches only the empty bare remote the harness makes for it under the results dir (`"remote": true`), never a network one; Bash allows only `date`, `TZ=…`, and `python3 …/mermaid-check.py`; edits allowed only under `plans/`, `reviews/`, and `architecture/`, so a review cannot become a code change. There is no page publisher to mock: a review page is a file in the pages dir, and `published` grades the html pages a turn wrote. Cases that explicitly supply a coordination context may provide mock peer tools (`evals/mock_peers.py`); this is fixture context, not knowledge carried by Frank. `AskUserQuestion` is answered by the harness acting as the host, from the case's `answer` spec, and every question is logged and graded. A denied call is still graded as an attempt.
- **Tests:** CI runs `cd evals && python3 -m unittest` on every push (Zach, 2026-10-05: "set up CI"). **Cases:** `python3 evals/run.py --arm baseline|agent --model sonnet [--case <glob>] [--runs N]`. **Sonnet for cases** (Zach, 2026-10-05: "use sonnet for tests", replacing the Opus-only rule of 2026-09-16): pass `--model sonnet`, because `run.py` still defaults to opus, and `--runs 3` before calling a case green. The agent frontmatter pins `model: opus` for the live run.
- **No hard wraps, no width caps.** A paragraph is one line in every file here, and no page caps the width of text. `hooks/no_wrap.py` is the one checker: the plugin's `PreToolUse` hook denies a Write or Edit with it, and the `flowing_text` grader fails a run with it.
- **No shell scripts.** Harness code, shims, mocks, and probes are Python (or another real language). Shell appears only as a one-line command someone types.
- **Fixtures are templates.** `{{today}}`, `{{yesterday}}`, `{{tomorrow}}`, `{{tz}}`, `{{now_hhmm}}`, `{{now±Nh}}` (`|local`, `|hhmm`), and `{{dotgit}}` (a `.git` dir name, since git cannot track one) in file names and contents. No hardcoded dates. An unknown token fails the run.
- **Fixtures are generic.** No data from any workspace that uses this agent — no patient data, no program documents, no real deploy names, no real session names.
- **The agent carries no workspace values or coordination protocol.** Paths, names, and the renderer location come from the workspace `CLAUDE.md` `## Architecture` block at run time. Communication instructions, when relevant, come from the assigning context.
- **One stage, then pause.** Each build stage is one red case turned green, reported with the red and the green output, then a stop for Zach. A session commits its own work in small meaningful commits, in its own worktree and branch; it reaches main only through a pull request.
- **Referenced from `~/Developer/ai-additions`** (`SETUP-LIST.md`, Referenced table). That repo's approval gate governs enabling.
